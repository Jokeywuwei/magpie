# MiniRelay Dark UI System（深色数据控制台风格）

> 版本：v1.6（2026-11-26）
> 状态：**门户视觉唯一规范**。后续 UI 任务默认按本文件执行。
> 参考来源：`https://aiapi.codes/dashboard/information` 的深色主题（2026-11-24 在真实浏览器中读取 `.dark` token 与组件计算值）。
> 适用范围：MiniRelay 用户门户（首页、登录/注册、概览、模型广场、模型管理）及共享组件；管理后台沿用同一套颜色/字体/圆角 token，但保留侧栏与 13px 紧凑密度，不改底部 Dock。

## 1. 北极星

> **像一块安静、精密的深色仪器面板：近黑底、发丝线、数据先行；白色只给主操作，颜色只给状态。**

一句话验收：遮住文字，只看底色、边框、圆角和 Dock，应该能认出这是同一个产品；遮住颜色，只看排版和间距，仍然清楚每一屏的主任务。

参考图的四个不可拆分特征：

1. **近黑哑光底 + 发丝边框**，卡片不靠阴影浮起。
2. **底部悬浮 Dock**，没有顶部大导航和侧栏（门户）。
3. **白色是唯一强主操作**；品牌蓝只用于链接、焦点和选中描边；彩色只做状态点/细条。
4. **数据密度高但留白足**：首屏第一行就是数据，表格/模型卡紧凑，区块之间留 28–32px。

只做其中一两个，就会退回“深色换皮”。

### 2.3 使用规则

- **背景**：页面 `--background`；卡片 `--card`；浮层/Dock `--popover`；控件选中 `--accent`；输入框外框 `--border`，聚焦环 `--ring`。
- **文字**：主文字 `--foreground`；说明/标签 `--muted-foreground`；不要再引入第三档灰色；禁用用 `opacity .5`。
- **主操作**：只有白底黑字一种；一屏最多一个 primary。
- **品牌蓝**：只用于链接、焦点环、选中描边、行内主操作（如“导入”）；不做大面积底色。
- **状态色**：只出现在 6px 圆点、细进度条、极小徽标、单行状态文字；不要整卡染色。
- **禁止**：蓝紫渐变、霓虹、玻璃拟态、彩色卡片、重阴影、深色底上再叠彩色发光。

## 3. 字体与排版

### 3.1 字族

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
  "Helvetica Neue", "Noto Sans", "PingFang SC", "Hiragino Sans GB",
  "Microsoft YaHei", Arial, sans-serif,
  "Apple Color Emoji", "Segoe UI Emoji";
--font-mono: ui-monospace, "SF Mono", Menlo, Consolas,
  "Liberation Mono", monospace;
```

参考站用系统字，不用 Inter/Geist。中文补 CJK 回退；数字 `font-variant-numeric: tabular-nums`。

### 3.2 字号与字重

| 角色 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| 页面标题 | 28–32px | 700 | 1.2 | 概览、模型价格、API 密钥、账单 |
| 区块标题 | 18–20px | 600 | 1.3 | 卡片组、资料区 |
| 卡片标题 | 14–16px | 600 | 1.35 | 卡片头、表格标题 |
| 正文 | 14px | 400 | 1.55 | 说明、表格内容 |
| 次要说明 | 12–13px | 400/500 | 1.5 | 标签、注释、表头 |
| 微标签 | 11–12px | 500/600 | 1.4 | 徽标、状态、分组标签 |
| KPI 数字 | 28–32px | 700 | 1.1 | 余额、Token、排名 |
| 次级数字 | 13–14px | 500 | 1.3 | 表格数字、单位 |

- 字重只用 400 / 500 / 600 / 700。
- 标题字距 `-.02em`；数字 `-.01em`；正文默认 0。
- 中文正文 ≥15px 时行高 ≥1.5；本系统正文 14px 用于紧凑表格，长说明用 15–16px。
- 页面标题不要放进卡片；卡片内不再放大标题。

## 4. 间距、圆角、层级

### 4.1 间距（4px 基数）

`2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 56 / 72`

| 场景 | 值 |
|---|---|
| 页面左右留白 | 32px（≤760 为 16px） |
| 内容最大宽 | 1376px |
| 12 列网格列距 | 16–20px |
| 卡片内距 | 20–24px |
| 卡片之间 | 16–20px |
| 区块之间 | 28–32px |
| 页头到首行内容 | 20–24px |
| 表格行高 | 56–64px |
| 表单字段间距 | 16–20px |

### 4.2 圆角

| token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | 8px | 按钮、输入、下拉、分段控件、菜单项 |
| `--radius` | 12px | 卡片、面板、表格容器、弹窗 |
| `--radius-lg` | 16px | 底部 Dock、资料大头像、浮层 |
| `--radius-pill` | 999px | 状态徽标、筛选胶囊、头像 |

规则：同一容器内的子元素圆角 ≤ 父级；不要出现 20/24px 大圆角。

### 4.3 阴影

- **卡片**：`box-shadow: none`，只用 1px `--border`。
- **Dock / 浮层**：`--elevation-float`，可叠加 16px backdrop blur。
- **选中滑块**：`--elevation-thumb`。
- **顶部高光**：`--elevation-raised` 仅用于可拖动滑块/选中项，不用于普通卡片。
- 同屏只允许一档浮起阴影。

## 5. 布局

### 5.1 门户主导航：底部悬浮 Dock

- 固定底部 16px，水平居中；容器 `--popover` 92% 不透明 + `backdrop-filter: blur(16px)` + 1px `--border`，圆角 16px，内距 8px。
- 图标按钮 48×48，圆角 14px，细线 22–24px 图标，间距 8px。
- 当前项：`--accent` 底 + 1px `--foreground` 环；悬停只提亮底色。
- 图标默认只显示图标；hover / focus-visible 在按钮上方 8px 显示文字 tooltip：`--popover` 92% + 1px `--border` + 8px 圆角 + 6px 10px 内距 + 12px/500，无阴影、无箭头，120ms 淡入上移；移动端禁用 tooltip，保留 aria-label。
- Dock 项由 `DOCK_ITEMS` 配置渲染：概览 `/portal/console`（order 10）、模型广场 `/portal/models`（20）、API 密钥 `/portal/keys`（30）、管理后台 `/`（40，仅管理员）、头像 `/portal/profile`（50，avatar）。**营销首页不占 Dock**，只经品牌 Logo / 页脚 Home 链接访问；HTML 里 Dock 是空容器，顺序/增删/隐藏只改配置数组。
- 移动端 Dock 保持底部，内容底部留出 Dock 高度 + safe-area；Dock 不遮挡内容。管理后台入口仅管理员渲染（不是隐藏）；个人资料页当前项用头像的白环高亮。
- **管理后台浏览器页复用同一 Dock**：`body.web` 的浏览器管理页没有顶栏和侧栏，页面标题在内容顶部，页面级工具在标题右侧；Dock 由现有 `#nav` / `#prefs` / `#portalLink` 代理生成（Providers、Routing、Routing groups、Gateway、Usage、Masking、Plugins、Settings、User portal），点击仍调用原按钮/链接。桌面窗口 `body.window` 保留顶栏、侧栏、拖拽与窗口按钮，不改成 Dock。

### 5.2 页头

- 左上页面标题 28–32px/700；下方可有一行 13px 说明。
- 右侧动作 36–40px 胶囊：一个描边次按钮 + 最多一个白底主按钮。
- 页头压成一行；移动端纵向堆叠。

### 5.3 内容网格

- 桌面 12 列；概览摘要条 4 等分；图表 3 列或 2 列；模型卡 3 列。
- ≤1100：模型卡 2 列，图表 2 列。
- ≤760：全部单列，摘要条 2×2，表格转卡片。

### 5.4 侧栏（仅管理后台桌面窗口）

- 桌面窗口 `body.window` 保留侧栏 212px 和 13px 紧凑密度，不改成 Dock；项目 30px 行高与分组标签 11px/500 不变。浏览器管理页 `body.web` 不显示侧栏，改用 §5.1 的 Dock。
- 侧栏底色 `--sidebar`，右侧 1px `--sidebar-border`；选中项 `--sel` 底 + 1px `--border` + `--mark` 字，悬停 `--pill`；圆角 8px。
- 门户不引入侧栏。

## 6. 组件

### 6.1 按钮

| 变体 | 底 | 字 | 边框 | 高度 | 圆角 |
|---|---|---|---|---|---|
| primary | `--primary` | `--primary-foreground` | 无 | 36–40 | 8 |
| secondary | 透明 | `--foreground` | 1px `--border` | 36–40 | 8 |
| ghost | 透明 | `--muted-foreground` | 无 | 32–36 | 8 |
| row-action | 透明 | `--brand` | 1px `--brand` 30% | 28–32 | 8 |
| danger | 透明 | `--danger` | 无 | 32 | 8 |

- 字重 500；字号 14；左右内距 12–16。
- 悬停：primary 提亮到 `#fff`；secondary 边框提亮；ghost 底色 `--accent`。
- 焦点：2px `--ring`，offset 2px。
- 禁用：`opacity .5`，不投影。

### 6.2 输入 / 下拉 / 文本域

- 高度 36–40（移动 ≥44）；底 `--background` 或 `--card`；1px `--border`；圆角 8；字号 14（移动 16）。
- 占位符 `--muted-foreground`；聚焦边框 `--ring` + 3px `--ring` 20% 光晕。
- 下拉右侧 16px chevron，整块可点。
- 错误：1px `--danger` + 12px 同色说明。

### 6.3 分段控件与筛选

- 高 32；轨道 `--background`/`--muted`；选中 `--accent`；圆角 8；字号 12–13；字重 500。
- 时间范围、状态筛选、表格视图切换都用同一组件。
- 胶囊标签（如“推荐”）用 999px、1px `--border`、透明底。

### 6.4 卡片

- `--card` 底、1px `--border`、12px 圆角、20–24px 内距、**无阴影**。
- 卡片头：标题 14–16/600 + 右侧动作；卡片内分隔用 1px `--border`（可更淡）。
- 一屏同类卡片不超过两组；分组优先用留白，不叠加卡片。

### 6.5 表格

- 容器：`--card` + 1px 边框 + 12px 圆角；无外阴影。
- 表头：12px、500、`--muted-foreground`；不强制大写。
- 行高 56–64；1px 行分隔；无斑马纹；悬停行 `--accent` 40%。
- 数字右对齐 + tabular-nums；操作列右对齐；状态列 6px 圆点 + 12px 文字。
- Key/ID 用 mono 12px，掩码显示。
- 移动端：每行一卡，字段带 `data-label` 标签。

### 6.6 徽标与状态

- 徽标：24px 高、1px `--border`、透明底、11–12px、圆角 999。
- 状态：成功 `--success`、警告 `--warning`、危险 `--danger`、信息 `--info`；只用于点/字/细条。
- 不要把整行或整卡染成状态色。

### 6.7 空状态

- 居中；48px 圆形图标底 `--muted`；标题 14/600；说明 12–13 `--muted-foreground`；上下留白 40–56px。
- 不使用插画；最多一个次级按钮。

### 6.8 弹窗

- 宽 `min(600px, 100vw-32)`；`--card` 底；1px `--border`；12px 圆角；`--elevation-float`。
- 遮罩 `rgba(0,0,0,.55)` + 8px 模糊。
- 头/脚 56px，1px 分隔；体 20–24px 内距；只体滚动。
- Esc 关闭并归还焦点。

### 6.9 底部 Dock 与客服

- 见 §5.1；Dock 是门户唯一全局导航。
- 客服：右下角 16px，胶囊 40px 高，`--popover` + 1px 边框 + blur。
- 移动端 Dock 图标可减到 4 个，但保留当前路由；不要隐藏主任务。

### 6.10 图表与数据可视化

- 折线/面积图：`--brand` 或 `--chart-*` 中的一色；网格线 `--border`；轴文字 11–12 `--muted-foreground`。
- 热力图：圆角 6–10px 方块，紫色 `--chart-4` 梯度；图例“少 → 多”。
- 可用率：4×8px 圆角小块拼成分段条，成功/警告/危险三色；不要整条大红大绿。
- 无数据时用空状态，不留空图表高度。

## 7. 页面模式

### 7.1 登录 / 注册

- 居中 420–440px 卡片；`--card`、1px 边框、12px 圆角、24–28px 内距；无阴影。
- 标题 24–28/700；说明 13–14 `--muted-foreground`。
- 输入 40–44px；主按钮白底黑字全宽。
- 错误条：暗红底（`--danger` 12%）+ 1px `--danger` 30% + 13px 文字。

### 7.2 概览（`/portal/console`）

- 页头：“概览” + 13px muted 说明 + 右侧账号动作；不显示 email/角色/注册时间。
- 第一行：4 格摘要条，竖细线分隔，只用当前时间范围的真实用量：请求、成功、失败、总 Token；数值 28–32/700，标签 12px muted。**不要伪造余额/套餐/充值。**
- 用量统计：标题 18–20/600；右侧时间范围分段（今天/昨天/近 7 天/近 30 天/全部）+ 现有 6 个统计，3×2 或 2×3 紧凑网格。
- 图表：每日用量、模型用量拆成 2 张独立卡片（≥1100 两列，≤980 单列）；空态用 §6.7，不留 166px 空白。
- 请求明细：标题 + 全部/成功/失败分段 + 模型筛选 + 自动刷新开关 + 刷新图标；表格按 §6.5，移动端转卡片。
- 概览不再放账号摘要、API Key 表格或管理后台说明卡；这些分别在 `/portal/profile` 与 `/portal/keys`。

### 7.3 模型广场（`/portal/models`）

- 桌面 ≥1100：左侧 220px provider 列表 + 右侧模型区，间距 24px；卡片网格 `minmax(340px, 1fr)`，最多 3 列，gap 20px；只有 2 个模型时两张卡占两列。≤760 单列，provider 列表变横向滚动胶囊。
- provider 行：20px 首字母/网格方块 + 名称 13px + 模型数 12px muted + 6px 状态点；行高 40，圆角 8，内距 0 10px；当前行 `--accent` 底 + 1px `--border`。
- 组头：provider 名称 20/600 + “N 个模型” 13px muted；右侧“全部/可用/不可用”分段 + 搜索；协议筛选在下方一行。
- 模型卡：`--card` 底、1px `--border`、12px 圆角、20px 内距、无阴影；顶部 32px provider 首字母方块 + 模型名 15/600 + 复制模型 ID 图标；第二行 6px 状态点 + “正常”/“暂不可用” 12px muted。
- 卡内信息块：有真实价格字段时显示“每 1M tokens”和输入/输出/缓存读取/缓存写入四行；没有价格字段时显示“模型信息” + 协议徽标 + 上下文、输入图片、协议、开放状态四行，缺失值用“—”。绝不编造价格、倍率、折扣。
- 可用性条：18 个 8×8px、3px 圆角、gap 4px 的小方块；只有真实可用/不可用时全绿或全 muted，不生成随机彩色或百分比。
- 底部：左侧 12px muted 可用状态，右侧“查看详情 >”品牌蓝；描述只放在详情弹窗。
- 搜索/Provider 过滤/协议过滤/可用状态过滤/详情弹窗/复制模型 ID 保留；焦点环 2px `--ring` offset 2px。
- 不伪造价格、倍率、折扣、延迟、可用率百分比；没有的字段用“—”。

### 7.4 API 密钥（`/portal/keys`）

- 页头：标题“API 密钥” + 13px muted 副标题；右上角“创建密钥”白底主按钮，旁边可放真实密钥数量徽标。
- 表格：名称、掩码 Key、模型授权、状态、操作；行内主操作蓝色描边；启用/禁用/删除为文字按钮；删除用 danger。
- 创建表单在页面卡片内展开；完整 Key 只显示一次；模型授权弹窗保留；空态/错误态保留。
- 不伪造分组、倍率、额度、并发。

### 7.5 管理后台

- 浏览器管理页（`body.web`）：页面标题 28–32/700 在内容顶部，右侧是页面级工具；底部是 §5.1 同一套固定 Dock，只有这一套底部导航；内容左右 32px（≤760 为 16px），底部留出 Dock 高度。
- 桌面窗口（`body.window`）：保留侧栏、顶栏、46px 标题栏和窗口拖拽/关闭按钮；套用同一 token、圆角、按钮、表格、弹窗。
- 两种形态都保留 13px 紧凑密度，不把管理后台改造成消费端大卡片。

### 7.6 首页（`/portal/`）

- 保持营销页定位，只做深色极简：标题、说明、白色 CTA、1px 细线卡片。
- 不做大渐变/彩色光晕；登录后主界面仍是概览。

### 7.7 个人资料（`/portal/profile`）

- 页头：“个人资料” + 13px muted 说明；右侧“退出登录”，管理员额外显示“管理后台”。
- 顶部大卡：居中 80px 头像（姓名首字母）+ 右上角角色徽标；姓名 20–24/600；UID 与“加入于 YYYY-MM-DD”，UID 旁复制按钮；四列统计（近一年 Token、单日峰值、当前连续、最长连续），移动端 2×2。
- Token 活跃度：全宽卡片，标题 + 每日/每周/累计分段；7 行 × 53 周热力格，10×10px、3px 圆角、gap 3px，`--chart-4` 五档；月份标签 11–12px muted；右下角“少 → 多”图例；无数据时全灰 + “暂无用量”。移动端横向滚动，首次显示最近月份。
- 账号信息：3 列 × 2 行网格，32px 图标块 + 值 14/600 + 说明 12px muted + 右侧描边小按钮；只放真实字段：邮箱、角色、注册时间、API Key 数量（管理密钥链接）、最近登录、账号 ID（复制）。
- 不实现产品没有的 OAuth 绑定、邀请返利、密码修改、设备管理；没有接口就不放按钮。
- 管理员卡片（模型开放、原管理后台、注册开关）只对管理员显示，放在账号信息之后；普通用户不可见。

## 8. 响应式与可访问性

- 断点：1100 / 980 / 760 / 390。
- ≤760：左右 16px；单列；表格转卡片；Dock 底部；输入 16px；可点目标 ≥44px；弹窗 `100vw-16px`。
- 320/390 不得横向溢出；`documentElement.scrollWidth = innerWidth`。
- 对比度：普通文字 ≥4.5:1；大字 ≥3:1；状态色文字必须达 AA。
- 焦点环：2px `--ring`，offset 2px；所有链接/按钮/输入/下拉/文本域可见。
- 键盘：Tab 顺序跟随视觉；对话框 Esc 关闭并归还焦点。
- 减少动效：`prefers-reduced-motion` 与设置项生效；过渡 120–220ms，曲线 `cubic-bezier(.2,.8,.2,1)`。

---

## 9. 内容与文案

- 页面标题用名词短语；不要“欢迎来到…”式营销句。
- 按钮写动作结果：`创建密钥`、`保存模型授权`、`导出 CSV`。
- 空状态一句话说清“为什么空 + 下一步”，不卖萌。
- 数字带单位；金额/Token 用 tabular-nums；时间用本地化格式。
- 不展示不存在的余额、套餐、价格、账单、返利；不伪造数据。

## 10. 验收清单

任何 UI 任务交付前必须逐项通过：

1. 深色 1440：背景 `#0a0a0a`、卡片 `#151515`、边框 `#2b2b2b`、卡片无阴影。
2. 门户底部 Dock 固定居中，当前项有白环；没有顶部大导航/侧栏。
3. 1440/1100/980/760/390 无横向溢出；320/390 文档宽 = 视口。
4. 移动端 0 个 <44px 可点目标；输入/下拉/文本域 16px。
5. 文字对比度 ≥4.5:1；焦点环可见；Esc 关闭弹窗并归还焦点。
6. 一屏最多一个 primary；彩色只出现在状态点/细条/徽标。
7. 所有卡片 12px 圆角、控件 8px、Dock/浮层 16px；无 20/24px 大圆角。
8. 真实浏览器截图：1440/390 × 中英 × 深色 + 1 张浅色回退；控制台 0 错误。
9. 功能回归：登录、创建 Key、模型筛选、详情弹窗、管理模型编辑、语言切换、主题切换。
10. 未新增路由/依赖/后端改动；未伪造业务数据；未 commit/push。

## 11. 与 oil-ui 的配合方式

后续任何 UI 任务按以下顺序执行：

1. **先调用 `oil-ui` skill**（全局用户指令要求）；这是项目视觉方向已确认的场景，直接走“继续已确认的方向”，不重新做三方向探索。
2. 读本文件与 `DESIGN.md` 的功能约束；先盘点现有页面/组件/变量，留基线截图。
3. 只从本文件的 token 取值；缺的组件先补到本文件，再写代码；不要在页面里临时加色值/圆角。
4. 真实浏览器实现与截图；按 §10 验收；需要时按 oil-ui 的存量润色流程做一轮独立评审。
5. 交付说明写：用了哪些 token、改了哪些页面、未做项、截图位置。

**不要**用 oil-ui 的通用风格建议覆盖本文件；**不要**在没有用户确认的情况下另起一套视觉方向；**不要**把参考站的品牌、Logo、文案、图片直接搬进产品。
